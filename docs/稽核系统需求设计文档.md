# 高速公路收费稽核系统需求设计文档


## 1. 项目背景
这个项目式是 /Users/moyuanming/getmoveobu 这个项目的一个重构项目
你需要读懂getmoveobu结合本项目需求复用getmoveobu该项目成果来完成本项目

> **架构说明**：本项目自重构以来,视觉识别(车型、车纹、出入口比对、货车套 OBU)和 LLM 二次判定已拆出为独立公共服务 `vehicle-ai-service`(部署在 `10.11.1.40:8081`)。主项目不再自部署任何 AI 模型;所有视觉识别通过 `apps.api.core.vehicle_ai_client` HTTP 客户端调用公共服务。

### 1.1 业务场景

高速公路收费稽核系统旨在检测以下逃费行为:

| 逃费类型 | fraud_type 标识 | 说明 |
|---------|------------------|------|
| **货车套用客车OBU** | `TRUCK_USES_PASSENGER_OBU` | 交易记录车辆类型=1(客车),但图片识别=货车,通过少交通行费逃费 |
| **出入口车辆不一致** | `ENTRY_EXIT_MISMATCH` | 比对出入口车辆图片,颜色/车型/车纹明显不一致,存在倒换通行卡逃费 |
| **门架路径异常** | `GATEWAY_ANOMALY` | 门架序列与拓扑不符(跳站、U 形折返) |
| **车型降档** | `VEHICLE_TYPE_DOWNGRADE` | 交易记客车(VEHICLETYPE=1),AI 识别为货车 |
| **同车牌多 OBU** | `SAME_PLATE_DIFF_VEHICLE` | 同一车牌历史绑定多个 OBU,疑似换 OBU 逃费 |
| **OBU 多车绑定** | `OBU_UNBIND` | 同一 OBU 短时间内绑多辆车,疑似 OBU 流转 |
| **OBU 屏蔽** | `OBU_SHIELD` | 客车记录无 OBU 但有出口图片,疑似屏蔽 OBU |
| **车牌 OBU 历史异常** | `PLATE_OBU_HISTORY` | 历史车牌-OBU 绑定关系异常 |

### 1.2 数据来源

- **主流水表**:`dwd_tolldata.t_waste_en_ex_gantry`(只读源库,生产 Doris)
- **门架抓拍流水表**:`ods_tb_toll_db_tolldata_prod.t_grantry_image`(门架图像关联)
- **站点字典**:`dwd_tolldata.t_md_tollstationdic`
- **关联字段**:`STATION_ID` = `t_md_tollstationdic.ID`
- **目标审计库**:`ods_AI_DB`(读写,承载 `audit_trips` / `audit_results` / `audit_actions` / `detection_rules` / `scheduled_tasks` 等全部派生表;原 SQLite 阶段已迁入,详见 §10)

### 1.3 门架数据结构

同一PASSID表示一次完整行程，包含：

| LANETYPE | 说明 |
|----------|------|
| 入口 | 车辆进入高速 |
| 门架 | 车辆路过门架（可有多条） |
| 出口 | 车辆驶出高速 |

## 2. 功能需求

### 2.1 行程聚合

**功能描述**：按PASSID聚合入口-门架-出口记录，生成完整行程

**聚合规则**：
- 同一PASSID = 同一行程
- 按LANETYPE区分交易类型
- 按OCCURTIME排序

**输出字段**：
| 字段 | 说明 |
|------|------|
| passid | 行程PASSID |
| entry_time | 入口时间 |
| entry_station_name | 入口站点 |
| entry_lane_id | 入口车道 |
| entry_vehicle_id | 入口车牌 |
| entry_vehicle_type | 入口车型(1=客车,16+=货车) |
| entry_vehicle_color | 入口车牌颜色 |
| entry_obu_id | 入口OBU |
| entry_media_type | 入口介质类型 |
| entry_image_license | 入口_license.jpg |
| entry_image_trans | 入口_trans.jpg |
| exit_time | 出口时间 |
| exit_station_name | 出口站点 |
| exit_lane_id | 出口车道 |
| exit_vehicle_id | 出口车牌 |
| exit_vehicle_type | 出口车型 |
| exit_vehicle_color | 出口车牌颜色 |
| exit_obu_id | 出口OBU |
| exit_media_type | 出口介质类型 |
| exit_image_license | 出口_license.jpg |
| exit_image_trans | 出口_trans.jpg |
| gantry_count | 门架数量 |

### 2.2 货车套用客车OBU检测

**功能描述**：检测单条记录中货车使用客车OBU逃费

**检测逻辑**：
1. 从交易记录获取 `VEHICLETYPE`（1=客车）
2. 下载 `_trans.jpg` 图片
3. 视觉模型 `VehicleClassifier.classify()` 识别车型
4. `VEHICLETYPE=1` 但 `识别=truck` → 标记可疑

**图片URL格式**：
```
http://{IPADDRESS}/img/data/{LANE_ID}/{date}/{ID}_trans.jpg
```

### 2.3 出入口车辆比对

**功能描述**：比对出入口车辆图片，判断是否为同一辆车

**检测逻辑**：
1. 入口下载 `_license.jpg`
2. 出口下载 `_license.jpg`
3. 比对各项差异

**比对维度**：

| 比对项 | 方法 | 阈值 |
|--------|------|------|
| 颜色 | HSV主色调分析 | 不一致→可疑 |
| 车型 | VehicleClassifier | 不一致→可疑 |
| 车纹 | ResNet50特征余弦相似度 | <0.6→可疑 |

**图片URL格式**：
```
http://{IPADDRESS}/img/data/{LANE_ID}/{date}/{ID}_license.jpg
```

### 2.4 稽核结果管理

**状态定义**:

| 状态 | 说明 |
|------|------|
| UNPROCESSED | 未处理(初始态) |
| PENDING | AI 复核中 |
| AI_VERIFIED | AI 复核完成(由公共服务判定 `is_same_vehicle`) |
| VERIFIED | 已核验正常(人工) |
| SUSPECTED | 可疑(人工标注) |
| CONFIRMED | 已确认欺诈(人工) |

> 旧文档中的 `LLM_VERIFIED` 状态在公共服务拆分后已统一更名为 `AI_VERIFIED`,字段 `audit_results.llm_*` 同步改名为 `ai_verify_*`(详见 §3.2)。

## 10. 双 Doris 库架构

生产环境使用两个 Doris 数据库,职责严格分离:

| 库名 | 角色 | 访问 | 用途 |
|------|------|------|------|
| `dwd_tolldata` | **源库** | 只读 | `t_waste_en_ex_gantry`、`t_grantry_image`、`t_md_tollstationdic` 等生产流水 |
| `ods_AI_DB` | **目标库** | 读写 | `audit_trips` / `audit_results` / `audit_actions` / `detection_rules` / `scheduled_tasks` / `task_executions` / `gateway_topology` / `migration_log` |

**连接层**:`apps/api/database/doris_connection.py`
- `get_connection()` 根据当前 SQL 的目标库返回对应连接
- 源库查询走 `READ_DORIS_*` 配置,目标库写入走 `WRITE_DORIS_*` 配置
- 旧 `apps/api/database/connection.py` SQLite 兼容层已下线,单元测试用 `temp_db` fixture 注入临时 SQLite 占位

**迁移路径**:`apps/api/database/migrate_sqlite_to_doris.py` 4 阶段:
1. schema 同步(SQLite DDL → Doris DDL,字段类型映射)
2. 全量数据导出(batched SELECT + 流式 INSERT)
3. 双写期(目标 Doris 与原 SQLite 并行写,比对结果一致性)
4. 切换读路径(读 Doris,SQLite 降级为备份)

## 11. 公共服务 `vehicle-ai-service` 集成契约

`apps.api.core.vehicle_ai_client` 是公共服务 HTTP 客户端,单例,默认 65s 超时。

### 11.1 端点清单

| 方法 | 路径 | 业务用途 | 调用方 |
|------|------|----------|--------|
| `compare(image_url_a, image_url_b, **metadata)` | `POST /api/v1/vehicle/compare` | 出入口双图"同一辆车"判定 | `services/vehicle_comparator.py` |
| `entry_exit(entry_url, exit_url)` | `POST /api/v1/vehicle/entry-exit` | 出入口视觉信号提取(颜色/车型/车纹) | `services/entry_exit_matcher.py` |
| `truck_obu(image_url, declared_vehicle_type=1)` | `POST /api/v1/vehicle/truck-obu` | 货车套用客车 OBU 检测 | `services/truck_obu_detector.py` |

> **注意**:公共服务**没有** `classify` 端点。`VehicleTypeDetector._classify` 改用 `truck_obu(declared_vehicle_type=1)` 反推车型:`is_truck=True` 视为货车,`False` 视为客车。

### 11.2 compare 端点 9 项元数据

透传给侧车分档裁决器,允许侧车在元数据完整时**完全绕开 LLM**:

| 字段 | 类型 | 来源 |
|------|------|------|
| `entry_vehicle_id` | str | `trip.entry_vehicle_id` |
| `exit_vehicle_id` | str | `trip.exit_vehicle_id` |
| `entry_obu_id` | str | `trip.entry_obu_id` |
| `exit_obu_id` | str | `trip.exit_obu_id` |
| `entry_color` | str | `audit_results.entry_color` |
| `exit_color` | str | `audit_results.exit_color` |
| `entry_visual_type` | str | `audit_results.entry_visual_type` |
| `exit_visual_type` | str | `audit_results.exit_visual_type` |
| `fingerprint_sim` | float | `audit_results.fingerprint_sim` |

`None` 值在客户端自动剔除,不进入请求体。

### 11.3 降级与错误契约

公共服务不可用时,客户端返回**降级 dict**(不抛异常):

```python
{'error': 'service_unavailable', 'detail': '<原始错误>', 'url': '<完整 URL>'}
{'error': 'parse_error', 'detail': 'status=XXX non-JSON', 'url': '<完整 URL>'}
```

业务封装(`truck_obu_detector` / `entry_exit_matcher` / `vehicle_comparator`)收到 `error` dict 或异常时,**返回安全的默认结果**(不阻断主流程)。

### 11.4 SSRF 白名单

`apps/api/core/image_utils.py` 下载图片时强制域名白名单,**禁止**:
- `169.254.x.x`(链路本地)
- `10.x.x.x` / `192.168.x.x`(内网)
- `127.x.x.x` / `localhost`(回环)
- `metadata.google.internal` / `169.254.169.254`(云元数据)
- 任意非 `http://` / `https://` 协议

## 12. JWT / OAuth 鉴权

`apps/api/core/auth.py` 实现双模式鉴权,通过 `AUTH_ENABLED` 环境变量切换:

| 模式 | 触发 | 流程 |
|------|------|------|
| **OAuth PKCE** | `AUTH_ENABLED=true` | 浏览器跳统一登录平台 → callback 拿 code → 后端换 token → 写 `token_cache` → 前端 `AuthGuard` 守卫 |
| **API_KEY** | `AUTH_ENABLED=false`(默认开发模式) | 静态 `X-API-Key` 头校验,适合内部调用与 CI |

**关键模块**:
- `apps/api/core/jwt_util.py` — JWT 公钥验签(RSA)
- `apps/api/core/oauth_service.py` — PKCE code_verifier 交换、refresh token 续期
- `apps/api/core/token_cache.py` — 进程内 5min TTL 缓存,避免每次请求都验签
- `apps/web/src/auth/AuthGuard.jsx` — 前端路由守卫,未登录跳 `/login`

## 13. 规则引擎与欺诈类型

### 13.1 8 类欺诈总表

| fraud_type | 触发条件 | 对应 `BaseDetector` | 实现状态 |
|------------|----------|---------------------|----------|
| `TRUCK_USES_PASSENGER_OBU` | `VEHICLETYPE=1` 且图片识别为货车 | `TruckOBUDetector`(调公共服务) | ✅ |
| `ENTRY_EXIT_MISMATCH` | 颜色/车型/车纹任一不一致 | `EntryExitMatcher`(调公共服务) | ✅ |
| `GATEWAY_ANOMALY` | 门架序列与拓扑不符(跳站/U 形折返) | `GatewayDetector`(读 topology 表) | ✅ |
| `VEHICLE_TYPE_DOWNGRADE` | 客车记录但 AI 识别为货车 | `VehicleTypeDetector`(调 `truck_obu` 反推) | ✅ |
| `SAME_PLATE_DIFF_VEHICLE` | 同一车牌历史 ≥3 个不同 OBU | `PlateObuDetector.detect_same_plate` | ✅ |
| `OBU_UNBIND` | 同一 OBU 短时间绑 ≥2 辆车 | `PlateObuDetector.detect_obu_unbind` | ✅ |
| `OBU_SHIELD` | 客车记录无 OBU 但有出口图片 | `ObuShieldDetector` | ✅ |
| `PLATE_OBU_HISTORY` | 车牌-OBU 绑定历史异常 | (规则引擎 DSL 表达) | ⏳ 规则引擎就绪后启用 |

### 13.2 JSON s-expression DSL

规则以 JSON 树形表达式存储在 `detection_rules.rule_expr` 字段,16 个白名单操作符:

| 类别 | 操作符 | 用途 |
|------|--------|------|
| 比较 | `eq` / `ne` / `gt` / `gte` / `lt` / `lte` | 数值/字符串比较 |
| 集合 | `in` / `not_in` | 枚举判断 |
| 存在 | `exists` / `is_null` | 字段非空判断 |
| 算术 | `add` / `sub` / `mul` / `div` | 数值运算 |
| 字符串 | `contains` / `starts_with` / `matches` | 文本匹配 |
| 复合 | `and` / `or` / `not` | 逻辑组合 |

**规则示例**:
```json
{
  "when": ["and",
    ["eq", "$trip.vehicle_type", 1],
    ["lt", "$audit.fingerprint_sim", 0.6]
  ],
  "score": 0.7
}
```

**`dry_run` 演练**:`detection_rules.dry_run=1` 的规则匹配后**只记录不落库**,用于新规则上线前的灰度验证。

## 14. 定时任务系统

`apps/api/services/task_scheduler.py` 守护线程,启动后**每 30s 轮询** `scheduled_tasks` 表,挑出 `enabled=1` 且 `next_run_at <= NOW()` 的任务交给 `task_executor` 执行。

### 14.1 5 种 `task_type`

| task_type | 行为 | 典型场景 |
|-----------|------|----------|
| `aggregate_detect` | 拉新流水 → 行程聚合 → 8 类检测 | 5min 一次的常规稽核 |
| `detect_only` | 已有 trip 上重跑检测(规则变更后) | 规则发布后的全量重检 |
| `multi_detect` | 多欺诈类型并发检测 | 阈值调优 |
| `re_detect` | 失败 trip 重跑 | 公共服务临时不可用后恢复 |
| `ai_verify_batch` | 批量 AI 复核可疑记录 | 30min 一次的复核队列 |

### 14.2 执行日志

- 任务开始时 `INSERT task_executions(status='running', ...)`
- 5s 一次的流式日志落库到 `result_summary` 字段
- 结束(`completed` / `failed` / `timeout`)后更新 `next_run_at = NOW() + interval`
- 失败重试:最多 3 次,指数退避

## 16. 测试体系

| 层级 | 工具 | 范围 | 现状 |
|------|------|------|------|
| **unit** | pytest + unittest.mock + temp SQLite | `services/*` 业务逻辑 | ✅ 318 用例,核心路径全覆盖 |
| **api** | pytest + httpx ASGI + temp SQLite | `routers/*` 接口契约 | ✅ 关键路由覆盖(可疑/行程/任务) |
| **e2e** | playwright | 关键 schema 与用户链路 | ⏳ 关键页面 smoke |

**核心约束**(写在 `pytest.ini`):
```ini
[pytest]
addopts = -v --tb=short --cov=apps/api --cov-report=term-missing --cov-fail-under=60
```

**CI 集成**:
- `build.sh` 在 `[0/5]` 阶段强制跑全量测试,失败 `exit 1` 不进前端构建
- `deploy.sh full` 模式在 `docker build` 前本地跑 `pytest -m "not slow"`,失败拒绝打包

**测试约定**:
- `from X import func` 产生的本地绑定要单独 patch(不能只 patch 源模块)
- 公共服务 mock 走 `httpx.MockTransport` 注入(避免新增 respx 依赖)
- Doris mock 走 `temp_db` fixture(临时 SQLite,自动 `%s → ?` 占位符转换)
